# CC-Relay 行为说明

本文说明 CC-Relay（下称"本应用"）在每种情况下具体会做什么、不会做什么。面向使用者，不涉及代码。

## 一、它是什么

本应用是 macOS 菜单栏里的小工具，用来在 Claude 桌面端的多个已登录账号之间一键切换。每个账号对应 Claude 的一个独立资料目录（默认账号是 `~/Library/Application Support/Claude`，其他账号是同一位置下的 `Claude_xxx`）。切换就是：关闭 Claude，再用目标账号的资料目录重新打开它。

菜单栏里是当前账号的小伙伴，和它在面板卡片上一样：表情跟着 5 小时额度变，颜色跟着每周额度变（见第八节）；它和旁边的图标一样大、方方正正，平时静止不动：额度升到或降到另一档时，它换上新的表情和颜色，升一档蹦一下，降一档叹口气；鼠标移到它上面时它动起来，移开后停下；切换账号后换成新账号的小伙伴。打开"减弱动态效果"时它始终静止。菜单栏里不显示账号名和百分比；当前账号和剩余额度都在面板里看。点开菜单栏图标是账号面板：最上面居中是带棕色描边的圆滚滚泡泡字"CC-Relay"（DynaPuff 字体，"CC-"浅陶土色，"Relay"薄荷绿），右边是刷新按钮（薄荷绿的圆箭头）和设置按钮（蜜桃色齿轮）；下面的大卡片是当前账号，当前账号用不了时紧接着出现推荐卡片（规则见第八节），再下面居中一个"+ 添加账号"的胶囊按钮，然后是其他账号的小卡片，点小卡片就切过去（见第三节）。只有一个账号时，小卡片的位置是一个虚线框，写着"还没有可以切换的账号 / 再添加一个账号，额度用完时就能切过去"。每个账号的头像都是同一个圆角方块小伙伴，表情和颜色跟着额度变（见第八节）。在卡片上点右键，或者鼠标移到卡片上时点名字右边出现的"⋯"，会弹出和面板同样风格的小菜单，只有"改名"和"移除"两项（见第五节）；菜单可以用方向键选、回车确认、Esc 关闭；打开"系统设置 → 键盘 → 键盘导航"后，按 Tab 也能把焦点移到"⋯"上；用旁白（VoiceOver）时，卡片上有"××× 的更多操作"。面板的高度随内容变化，最高 720 点，屏幕放不下时停在屏幕底部上方：账号多到放不下时，标题、当前账号和推荐卡片留在原处，下面的账号小卡片上下滚动，滚动后两部分之间出现一条细线（macOS 15 及以上）；切换、添加、改名、移除都在面板正中弹出的对话框里进行，背后的页面变暗、点不到，面板不够高时会长高到放得下对话框；需要你处理的提示（发现账号、导入中断、需要钥匙串授权、自动切回、压缩结果、要看一眼的操作结果）以对话框出现在面板正中，背后的页面变暗、点不到，一次只出一个，处理完或点"知道了"才出下一个；点了"知道了"的提示在它还在时不再出现，它消失后再出现时会重新弹出；顺利完成的切换和添加在各自的对话框里打勾，停一下就缩小消失；其他顺利完成的操作结果（例如"已移除 ×××"）和"正在切回…"以一张小卡片浮在面板正中，不挡操作，过一会儿自己消失。卡片上不显示邮箱。点面板以外的地方、按 Esc、切到别的应用或再点一次菜单栏图标，面板就会收起。每次打开面板都会刷新各账号的额度。

面板里的变化带有简短的动画：设置页从右侧滑入，各组设置依次升起，返回箭头弹进来、鼠标移上去时往后一仰；齿轮在鼠标移上去时转动、按下时多转一点；对话框和右键菜单弹出，浮在中间的小卡片弹出后淡出；额度条、百分比和小伙伴的表情随新数据平滑过渡，等待登录、等待任务和压缩时有转圈，切换对话框里的步骤一步步打勾，进度条上正在进行的那一步有一道流光；套餐标签的颜色一直横向流动，每隔几秒还有一道光扫过；小伙伴会动（见第八节）；按下卡片时卡片微微缩小，设置里的开关滑块弹过去、按住时拉长。在"系统设置 → 辅助功能 → 显示"里打开"减弱动态效果"后，这些都不动，直接显示结果。面板收起后，里面的动画全部停下，不占用电脑；再打开时接着动。

## 二、第一次启动

第一次启动时，自动登记本机所有已登录的 Claude 资料目录。名字取邮箱 @ 前面的部分；暂时拿不到邮箱时，默认账号叫"默认账号"，其他账号用目录后缀，之后第一次读到邮箱会自动改成邮箱名（你手动改过名的不会再被改）。

## 三、一键切换

点一下非当前账号的卡片（或推荐卡片），面板正中弹出切换对话框：上面是当前账号和目标账号的两个小伙伴，中间三个点从左往右跳。

- **先问一次（设置里的"切换确认"，默认开启）**：对话框先问"切换到 ×××？"，下面写着 Claude 会关闭并用它重新打开、刚才的对话会自动打开，可以选"切换"或"取消"（Esc 也是取消）。勾上"以后不再询问"再点切换，"切换确认"就关掉，之后点卡片直接切换；在设置里可以再打开。本应用自己发起的切换（默认启动纠正、自动切换）从不询问。
- **进度**：点了"切换"，对话框直接变成四个步骤（关闭 Claude → 备份并同步会话 → 用 ××× 打开 Claude → 打开你刚才那段对话），做完的打勾，正在做的转圈，下面一条进度条；对话很长时，先显示"先压缩当前对话"（见第 3 步）。有 Code 任务在运行时，对话框换成任务守卫的问题（见第 2 步）。
- **完成**：四步都打勾后，目标小伙伴跳一下，对话框停一下就缩小消失，目标账号成为当前账号。
- **失败**：没完成的那一步打红叉，目标小伙伴叹口气、角上一个红色"!"，下面写原因，可以"重试"（不再询问）或"关闭"。

1. **先检查，再动手。** 目标账号目录不存在或读不了配置、已有别的操作进行中，都会直接拒绝，此时 Claude 不会被关闭。点的就是当前账号且 Claude 开着，则什么都不做。Claude 完全没开（连残留的后台进程也没有），就跳过任务守卫和关闭，同步后直接打开目标账号。Claude 主程序已经退出、但还残留辅助进程或 Claude Code 任务（例如 Claude 崩溃后）时，按"Claude 还开着"处理：照常检查任务、关干净后再切换。
2. **任务守卫。** 如果 Claude 里有 Claude Code 任务正在运行（在等你授权、正在跑命令的也算；或者无法确定），切换对话框里会问一句，标题写着有几个 Code 任务在运行（无法确定时写"无法确认有没有 Code 任务在运行"），下面三个选项：
   - **等任务结束后切换**：每 5 秒检查一次，对话框里显示"正在等待任务结束…"，任务都空闲后自动继续，不再询问。
   - **立即切换**：直接强制关闭 Claude，不再出现 Claude 自己的"Claude 仍在处理中"退出确认；正在运行的进程会被立即结束，来不及收尾（例如 git 可能留下锁文件），Claude 也来不及保存自己的状态（例如输入框里还没发出去的文字）。自动同步开着时，托管的后台命令不会中断，其他符合下文续接条件的工作会在目标账号里核验进度后继续。
   - **取消**：什么都不改变。
3. **记下当前对话，长对话先压缩。** 关闭前记住你在当前账号里最后聚焦的那段对话，用于切换后"续接"。这段对话的上下文达到 30 万 tokens 以上、并且第九节的自动压缩开着时，先让它在当前账号上压缩好，再关闭 Claude：
   - 原因：提示缓存按账号区分。不压缩就换到新账号继续，第一条消息要把整段上下文重新计入新账号的额度；在老账号上压缩，只需从老账号的缓存里读一遍，新账号只用写入一份简短的摘要。
   - 切换对话框显示"先压缩当前对话"和"正在压缩，约需 1–3 分钟…"，可以点"跳过，直接切换"。压缩由这段对话里的压缩插件执行（和第九节是同一个插件），压好后自动接着切换。压缩一旦开始，就等它压完（最多再等 10 分钟），不会在压缩中途关掉 Claude，免得白压。等待期间如果有 Code 任务开始运行，压缩结束后关闭 Claude 前会再问一次，和切换开始时的询问一样。
   - 下面这些情况不等压缩、直接切换，结果里写"已切换，但对话没能先压缩"：插件没有在报到（没装、被关掉，或这段对话没开着），或者这段对话里还是旧版插件（它不会回答，所以不去问它，也就不用干等）；插件回答这次压不了（例如这段对话最近一小时没用过、额度已经用到 99%，或者 Mac 上另一段对话正在压缩、一直没轮到）；压缩没成功；3 分钟内既没开始压缩也没回答；开始压缩后 10 分钟还没压完。
   - 你点了"跳过，直接切换"，或者在任务守卫里选了"立即切换"，就不压缩，结果里也不提。Claude 本来就没开、第九节的开关关着、对话不到 30 万 tokens 时，都不压缩、不提醒，照常切换。
   - 压缩阈值判断只读取对话记录最后一条回复里的用量数字；Claude 自己写入的提示（例如"额度已用完"）不算回复，会往前找；对话刚压缩过、还没有新回复时，不再压缩。下文的原生续接还会读取结构化历史，确认原任务及其结果。
4. **关闭 Claude。** 先记下"切换后需要重新打开哪些账号"（目标账号，以及除了你要离开的账号之外所有正开着的账号），这份记录写在磁盘上，某个账号真正打开之后才从记录里划掉：即使本应用中途退出或崩溃、或者某个账号这次没能打开，下次也会补开（本应用下次启动时就补，已经开着别的 Claude 窗口也一样），之后再切换几次也不会把它忘掉（你自己把它打开了，就从记录里划掉）；已经开着的账号不会被重复打开。关闭的方式：
   - 你选了"立即切换"时，不先正常退出，也不等宽限，直接精确地强制结束（规则同下面"还没退出的"那一条）；
   - 先正常退出（等同于 ⌘Q，让 Claude 自己保存状态），最多等 20 秒；
   - 主程序都退出后，残留的子进程（例如 Claude Code 命令行进程）再给 5 秒宽限；
   - 还没退出的，先确认不会打断刚开始的任务（你选了"立即切换"时不检查；确认期间已经自己退出的，就算关好了），再精确地强制结束：只结束关闭开始时记录在案、并且身份（进程号、启动时间、程序路径）完全对得上的进程；
   - 关闭途中你自己又打开了 Claude，会立即停手，不碰新打开的窗口；
   - 没能全部关掉时，只把已经确认关干净的账号重新打开，不做任何同步，并提示"无法关闭 Claude"。这时有账号没能重新打开的，也会记下来，下次补开。
5. **自动同步（设置里可关，默认开启）。** 两个账号都已登录且组织信息完整时（Claude 本来就没开时也同步），先分别备份两边的会话目录，再双向同步对话记录（详见第六节）。备份或同步出问题不会中止切换，只在结果里提醒，例如"已切换，但有 3 个会话没能同步"。
6. **打开目标账号。** 同步后确认刚才那段对话在目标账号里仍然完整可用，就带着它的链接打开目标账号，让 Claude 直接回到这段对话；其他原本开着的账号也会一并重新打开。自动同步开着并装有当前版本的 CC-Relay 插件时，还会让原账号里没做完的工作在原会话里接着做：先核验新运行时确实属于目标账号，再继续，具体规则见下文。打开窗口和恢复工作是分别确认的。
7. **结果。**
   - 成功时目标账号成为当前账号，并立即刷新它的额度。
   - 之后 90 秒内在后台确认对话确实被重新打开；没有确认到时补充提醒"没能重新打开上次的对话"（这是提醒，不算切换失败）。切换完成的对话框一两秒就会消失，到那时它已经不在了，这条提醒会单独出现；之后又有了别的操作，就不再提这件旧事。
   - 切换成功但有要你知道的事（例如有会话没能同步、对话没能先压缩），对话框照样消失，提醒以提示框出现在面板正中，点"知道了"收起。
   - **打不开就回到原账号**：如果目标账号在 30 秒内没能打开，本应用先把这次启动、但没能确认的那个 Claude 关掉（先正常退出，10 秒后仍未退出才强制结束；切换前就开着的 Claude 不会被动），再重新打开你刚才离开的账号并回到原来的对话，切换对话框里写"××× 没能打开，已回到 ×××。"。只有原账号也打不开时才写"没能打开 Claude"。

### 原有工作如何续接

切换账号必须先关掉 Claude，Claude 一关，它正在跑的东西都会停下。自动同步开着、并且装有当前版本的 CC-Relay 插件时，本应用会在关闭前记下原账号里还有工作的会话，在目标账号里让它们接着做，不用你再输入"恢复任务"，也不用改用别的工具。

| 原有工作 | 换号后 |
|---|---|
| 主会话 | 自动收到一条只有一句话的续跑消息，Claude 根据原会话历史继续没做完的部分。哪些工作已经接回、哪些受阻，记在本地回执里，不写进消息。 |
| 子代理 | 被这次切换打断的子代理按原来的编号、用它自己的历史继续。已经完成、你停掉的、在等你回答的，不会被重做或另建一个代替。 |
| 后台命令和命令监听 | 你的权限规则或当前模式直接放行的命令（"跳过授权"模式下一般就是全部），从启动起交给一个独立的小程序运行，换号时不停，新账号里接上同一个进程和它的输出。需要你点授权的命令，以及设了 PreToolUse 钩子时的所有命令，照原样运行，换号时会停下，由 Claude 根据原来的输出判断要不要重启。 |
| WebSocket 监听 | 按原来的参数和剩余时限重新建立。换号那几十秒里推送的消息，只有对方服务能补发时才不会丢。 |
| 网页（Artifact）评论监听与自动回复 | 网页属于发布它的账号，别的账号打不开它，所以监听留在原账号，不会转过去：只挂着评论监听的空闲会话换号时不打开；和别的工作一起接续的会话照常在新账号接着做，新账号不去连它的监听，也不因此提示"接续受阻"。面板提示"评论监听留在了 {原账号}"，列出这些会话；切回原账号时，还在做事的会话连同监听一起接回，已经空闲的会话只为监听在后台启动，不开始新回合。会话后来又被带到第三个账号，监听仍算在发布网页的那个账号上。同一账号里普通重开会话时，检查原网页并补接原来启用的监听。连接与自动回复分别检查；原来启用了自动回复时按需恢复，宿主拒绝或当前账号权限不足时在原会话里提示。纯监听只有在宿主明确确认已连接且未启用回复时才算恢复；需要新建而宿主不能保证纯监听时在原会话里提示，不擅自启用回复。原记录读取失败会重试，连续失败后显示具体原因。主动停止的监听、关闭的自动回复以及另一会话正在处理的回复，不会被强行重开，也不会重新发布网页。 |

- **授权不变**：托管不改变授权。弹窗、自动模式的安全检查和你设的钩子看到的都是真实命令；托管的命令不会多弹一次授权，也绕不过原来的拒绝。命令里用到的 shell 函数和别名照常可用，任务列表里仍显示原命令。
- **其他会话**：切换时你正在看的那段对话直接打开。其他还有工作的会话由本应用逐个打开，不需要任何系统授权；但只在目标账号的 Claude 是唯一开着的 Claude 时才自动打开。同时开着别的账号的 Claude 时，面板提示"接续受阻"，这些会话需要你自己打开（24 小时内打开仍会接着做）。
- **托管命令等多久**：Claude 关掉后，托管的命令先保留 5 分钟；会话还没在目标账号里打开时会自动延长，最长到自动打开阶段结束后再多 5 分钟。这段时间里都没人接手，命令就会被结束，不会在后台无人看管地一直跑。从界面或用 TaskStop 停止托管的命令，会连同它启动的子进程一起停下。
- **不重复，不抢话**：已经做完的、你明确停掉的任务不会复活；换号后你一发新消息，或者在续跑时按停止，自动续跑就让给你。续跑正在进行时你发话，续跑的这一轮马上停下，你的话在新的一轮里照常执行；按回车、用 ctrl+x 回车排队发的消息和斜杠命令都一样。切换时正在回复的对话，Claude 重新打开后会自己发一句"接着做"（The app was quit while you were working…，换个说法也认得出）；这时由本应用的续跑代替它，只续跑一次，托管的后台命令照常接回；续跑没来时，这句照常发出。命令失败、历史不完整、权限不足或资源不可用时，Claude 先说明问题，不会猜参数、重复已经做过的操作或把失败当成功。关闭 Claude 造成的中断，和你在切换前主动按下停止分开处理：切换前你停下的回复，换号后不会自动接着做。
- **面板**：换号后面板中间有一条接续提示，只有三种状态："正在接续"（图标是三个点）、"接续成功"（对勾）和"接续受阻"（黄色感叹号）。前两种的第二行写明从哪个账号换到哪个账号。"接续成功"表示每段会话的续跑这一轮已经做完（只用文字把回复写完也算），或者工作在关闭期间已经完成；它不代表原任务已经完成，也不保证每个监听都已连上，任务是否真正完成要看原会话里的结果。"接续受阻"后面跟一句原因，原因不止一种时说有几段会话没能接续；点"查看本地记录"打开记录文件夹。新账号上的会话大约要半分钟才报到，所以换号后的头 30 秒里只显示"正在接续"，自动切换也不因为它们还没报到而暂停。状态变了会重新提示；全部结束、你在面板里看过之后，提示会在面板关闭时消失。
- **你自己决定的事不提示**："接续受阻"只留给真正需要你看一眼的情况。切换前你停下的回复、换号后你接手的续跑、你自己停掉的接回任务，都不算问题，面板不会提示；接回的命令后来自己失败或结束，也是命令本身的结果；续跑做完以后你再发话或按停止，它的结果也不变。续跑中某一步失败（比如测试没通过）属于正常工作，只有续跑动过的工具全部失败才报"接续受阻"。
- **停下的回复留下的后台命令**：切换前你停下了回复，但它启动的后台命令（比如构建、测试）还在跑，这些命令会随切换结束，不会带到新账号；面板用一条普通提示"切换时结束了 N 个后台命令"告诉你，要不要重新跑由你决定。命令在切换前已经自己结束、或已经被你停掉的，不算在内。
- **范围**：只针对这次切换离开的账号里原本开着的会话；同时开着的其他账号仍按原规则补开窗口。Claude 原本完全没开时，光有历史记录不会让旧任务复活。快速连续切换时旧请求作废；目标打不开而退回原账号时，只向重新核验后的原账号续接。备份或同步失败时不发出续跑请求。
- **做不到的**：不关 Claude 直接换号（官方接口不支持）；插件加载之前就在跑的命令；需要授权才运行的命令保持原来的进程（它们换号时会停）。

原生续接和自动压缩共用 `cc-relay` 插件，安装方法见第九节。关闭"自动压缩"只关掉压缩；关闭"自动同步"后，之后的切换不再续接原有工作。已在 Claude 里开始的工作仍由 Claude 自己的停止操作控制。实现方式、验证范围和已知限制见[原生工作续接](native-work-continuity.md)。

## 四、默认启动纠正（始终开启）

如果有人不经过本应用打开了 Claude（例如从程序坞、聚焦搜索，或 Claude 自动更新后重启），Claude 会落在默认账号上。本应用发现后会关闭它，改为打开你当前选中的账号，并显示"Claude 打开的是默认账号，已切回 ×××"。这一步不做同步，强制结束前同样会检查任务。为防止反复横跳：60 秒内第二次出现就暂停纠正 10 分钟，并显示提示。

## 五、账号管理

- **添加账号**：点"+ 添加账号"后，面板正中弹出添加对话框，一路显示进行到哪一步：正在关闭 Claude、在弹出的 Claude 窗口里登录新账号（可以"取消添加"）、正在导入历史会话、正在打开 Claude。结束时有三种：添加好了（写"已添加 ×××"和它的套餐、订阅渠道，停一下就消失，新卡片出现在列表里）；登录的是列表里已有的账号（见下面）；没能添加（写原因，可以"重试"或"关闭"）。具体过程：先检查任务、记下当前账号的 Claude Code"跳过权限确认"选择和要导入的历史来源，然后关闭 Claude；关闭成功后才新建一个空的 `Claude_xxxxxx` 目录，用它打开 Claude，等你在弹出的窗口里登录（每 2 秒检查一次，登录完成且组织信息就绪后才算完成）。名字取邮箱 @ 前面的部分，重名时加 -2、-3。中途失败会把原来开着的窗口全部重新打开，不会留下半成品；新账号的 Claude 打不开时也一样：空的新目录移到归档，不会留下"等待登录"，并提示"无法打开 Claude"。
  - **登录的是已有账号**：对话框写"这个账号已经在列表里了（×××）"，由你选择"保留两个"或"放弃新添加的"（放弃的新目录移到归档）。
  - **取消添加**：关闭 Claude，把新目录归档（不删除），重新打开你原来的账号。
- **新账号导入历史会话**（自动同步开启时）：新账号登录后，把其他每个已登录账号的对话记录单向复制进新账号，这样新账号一开始就能看到所有历史对话（双向同步只覆盖切换的那两个账号，这一步补齐其余账号）。导入前先备份新账号的会话和配置文件。只有会话全部复制成功，才继承你原账号的"跳过权限确认"选择，而且遵守三条规则：目标账号自己已有选择就不动；原账号选了"开启"时，只有目标账号本身已具备开启资格才继承；从不复制资格本身。导入失败或部分来源账号不可用时，弹出提示和"重试"按钮，只在你点重试时再执行，绝不自动反复关闭 Claude。添加时自动同步是关闭的，导入意图会保留，打开自动同步后再执行。
- **重新登录**：账号登录失效时卡片上额度的位置是一个红色小框，写着"需要重新登录"。点它会切换到该账号，Claude 会显示登录页；登录的必须是原来那个账号，换成别的账号会提示而不会被悄悄接受。登录一确认就立刻重新读一次额度，卡片马上恢复，不会还停在"需要重新登录"。等你登录期间，服务器已经拒绝过的那份登录信息不会反复拿去问，只有 Claude 写入新的登录信息（也就是你重新登录了）才去确认一次；切换到别的账号后，就不再等这个账号登录。
- **改名**：卡片菜单 → 改名，面板正中弹出改名对话框，输入框里是原来的名字；1–20 个字符，任何文字都可以。回车保存、Esc 取消；空着或超过 20 个字时，输入框下面红字说明，不保存。
- **刷新额度**：点面板右上角的刷新按钮，重新读取所有已登录账号的额度：读取时箭头转动、百分比一闪一闪，读完数字跳一下、箭头回弹停下，面板中间浮出"额度已更新"。箭头至少转 0.7 秒，读得再快也看得见。切换等操作进行中时按钮变灰、点了没反应。
- **当前账号跟随 Claude**：用别的工具切换了账号，或你自己用别的方式打开了另一个账号，本应用发现记住的"当前账号"并没有开着时，会把 Claude 实际开着的那个已添加账号标为当前；同时开着几个时，以最后打开的为准。从程序坞、聚焦搜索直接打开的默认账号不算，那是"默认启动纠正"的事。切换、添加等操作进行中不做这一步。
- **发现账号与忽略**：发现本机有已登录、但还没添加的 Claude 资料目录时，面板中间弹出"发现账号 ×××"，可"添加"或"忽略"。忽略后它列在设置的"已忽略的账号"里，随时可以"重新添加"；Claude 每次打开一个被忽略的账号，提示都会重新出现；在它开着时再点"忽略"，提示就收起，直到下次打开。新弹出的对话框在最初约 0.6 秒内不响应点击，避免它正好弹在鼠标下面时误点。
- **移除**：卡片菜单 → 移除，面板正中先问"移除 ×××？"，写明账号文件夹会移到归档文件夹、不会删除。当前账号菜单里的"移除"是灰的，下面写"正在使用的账号不能移除"。确认后卡片马上从列表里消失，面板中间浮出"已移除 ×××"和"撤销"按钮，4 秒内点撤销，账号原样回来，什么都没动（这 4 秒里打开了别的对话框时，提示先让开，对话框关掉后还没到 4 秒就重新出现）；4 秒过后（有切换等操作在进行时，等它做完）才真正移除。在这 4 秒里又移除另一个账号，前一个立即移除，后一个照样有自己的 4 秒；这 4 秒里退出本应用，账号不会被移除。真正移除时如果被拒绝，账号回到列表，并提示原因。最后一个账号、正在运行的账号（或无法确定是否在运行）都不能移除。账号的窗口虽然关了、但它留在后台的进程（比如还在跑的 Code 任务）还在时，也算正在运行；有说不清属于哪个账号的 Claude 后台进程时，算无法确定，先不移除。移除就是把账号目录整体移到本应用的 `Archive/` 目录，然后从列表、待登录、导入任务、"需要重新打开的账号"记录和额度缓存中清掉；数据不会被删除。

## 六、会话同步规则

- 只同步对话记录文件 `local_*.json`。Claude 的定时任务文件 `scheduled-tasks.json`、等待输入目录 `waiting-input/` 和删除标记都不会被复制，避免定时任务在多个账号里重复执行。`~/.claude/projects/` 里的对话正文从不改写。
- 某账号删除过的对话（目录里有删除标记）不会被同步回来。
- 两边都有同一段对话时：内容相同则跳过；一边没有则复制过去；修改时间更新的一方覆盖旧的；无法判断新旧时两边都保留，并计入"没能同步"的数量。
- 同步后按实际存在的对话重建归档列表 `archived-sessions.idx`，保持你在每个账号里的"已归档"状态。
- 每次写入都是先写临时文件再原子替换，保留原文件的权限和修改时间。

## 七、备份与回收

- 任何写入账号目录的操作（同步、导入）之前，都会先备份该账号的整个会话目录（导入时连同 `claude_desktop_config.json`）。备份先写到临时目录，完整后才改名生效；内容没变时复用上一份。
- 每个账号保留最近 5 份备份，更早的移入回收区 `Backups/.trash/`，30 天后才真正删除。设置里"打开备份文件夹"可直接查看。
- 被移除的账号在 `Archive/`，被取消的新账号目录也在这里，都不会自动删除。

## 八、额度、套餐与订阅渠道

- 每张卡片显示套餐（Free / Pro / Max / Max 5× / Max 20× / Team / Enterprise）、订阅渠道（网页 / App Store / Google Play），以及 5 小时和每周两个额度的**剩余**百分比和重置时间：5 小时显示"21:00 · 2 小时 30 分后"，每周显示"10月29日 周四 21:00"。倒计时每分钟自动更新。
- **额度颜色**：额度条和百分比按剩余量分四色：超过 50% 绿色，30%–50% 蓝色，11%–29% 黄色，10% 及以下红色。
- **套餐标签**：像游戏里的稀有卡牌，亮面、浅色描边、外发光、白色粗体字，颜色一直横向流动，每隔几秒还有一道光扫过，浅色和深色外观下一样。Pro 是几种紫色；Max 5× 和看不出档位的 Max 是手游卡片那种金色；Max 20× 是彩虹；Team、Free、Enterprise 等其他套餐是青绿色。打开"减弱动态效果"后颜色不流动、不扫光。
- **头像小伙伴**：和额度条一样分四档。表情看 5 小时额度剩多少：超过 50% 大笑，30%–50% 微笑，11%–29% 有点发愁，10% 及以下半闭着眼打哈欠。颜色看每周额度剩多少：超过 50% 浅绿，30%–50% 浅蓝，11%–29% 浅黄，10% 及以下浅红。每周额度用完时变灰、闭眼睡着、头上有个"z"，不管 5 小时还剩多少，因为这时账号用不了。读不到额度时（需要重新登录、正在等待登录、暂时无法获取额度）是灰色，睁着眼，嘴是一条直线。头像不区分账号，认账号看名字。额度显示的是旧数据（"更新于 HH:mm"）时，小伙伴按卡片上显示的数字变。
  - **小伙伴会动**：越有精神动得越欢、站得越直，越累越蔫：大笑的蹦跳、东张西望，微笑的轻轻摇晃、眨眼，发愁的耷拉眼皮、偶尔一抖，打哈欠的点头打盹，睡着的慢慢呼吸、冒"z"。眼睛跟着鼠标看（越有精神看得越远，睡着的不看）。每隔一会儿，会有一个小伙伴做个小动作（按精神挑：转圈、扭一扭、歪头、伸懒腰、甩甩头、瘫一下、打个盹、翻个身）。鼠标移到卡片上，它会跳一下或惊醒一下。新读到的额度让它精神了一档时它会振作一下，累了一档时叹口气；切换时目标小伙伴兴奋地跳。每个账号的小伙伴节奏不同，不会整齐划一。打开"减弱动态效果"后，小伙伴都不动。
- **推荐卡片**：只在当前账号用不了时出现：5 小时额度剩不到 10%、每周额度用完，或者读不到额度（没有当前账号时也出现）。当前账号还能用时这里什么都不显示，因为切换要重启 Claude，长对话到了新账号上还要整段重新读一遍，不值得为了先用掉别的账号快到期的额度去切。卡片在当前账号下面，布局和当前账号的大卡片一样，点它就切到那个账号，和点它的小卡片一样（有任务在跑时同样先问）。它从其他账号里挑：每周额度还有剩、5 小时额度至少剩 10% 的账号里，每周限额重置**日期**最近的那个。按日期比，不按小时；同一天重置的，5 小时剩得多的优先，再一样就重置时间早的优先；每周额度还没开始计时的排在后面。每周额度剩不到 5% 的排在最后，其他账号都用不了时才选它：长对话过去可能几分钟就把它用完，又要关开一次 Claude。自动切换选号也是这样。正在删除的账号不参加；和当前账号是同一个登录（同一账号、同一组织）的文件夹也不参加，它们共用一份额度，切过去也不会多出额度。
  - 卡片标"推荐"（绿色），最后一行写"周限额 10月27日 周二 重置，日期最近"（推荐账号的每周额度还没开始计时时写"每周额度未计时"），分号后面写当前账号用不了的原因："当前每周额度已用完"（两个都用完时说这个）、"当前 5 小时只剩 7%"或"当前账号额度读不到"。没有当前账号时只写前半句。
  - 其他账号也都用不了：没有卡片，换成一行字"暂时没有可用的账号，等额度恢复"。只有一个账号时这里什么都不显示。
- **读取方式**：从该账号资料目录的 Cookie 中解密登录凭据（需要读取钥匙串里的"Claude Safe Storage"，首次会弹系统授权框），然后只访问 claude.ai 的三个接口：账户信息、用量、订阅详情。凭据只在内存里使用，从不写入文件或日志。本应用每次启动时先取一次密钥（选过"始终允许"就不会弹窗），所以刚启动就打开面板也能直接读到额度；打开面板本身从不向钥匙串要授权。
- **刷新节奏**：当前账号每 10 分钟左右刷新一次，切换后立即刷新；每次打开面板，都会同时重新读取所有账号（只有 30 秒内刚读过的账号不重复读，免得连续点开时重复请求）；自动刷新时，同一账号 2 分钟内不会重复请求；订阅渠道每天最多查一次。额度读取不访问其他服务；Claude 中的压缩、续跑和工具调用仍会按原任务联网。
- **钥匙串被拒绝**：之后的自动刷新不会再弹授权框，面板中间弹出"需要钥匙串授权才能读取额度"和"重试"按钮，点重试才会再次请求授权。
- **读取中**：从来没读到过、正在读的账号，额度条的位置是两组灰色的占位条。
- **离线或读取失败**：继续显示上次成功的数据并标明"更新于 HH:mm"；从来没读到过时，使用 Claude 自己记录的历史用量百分比。实在读不到时，额度的位置是一个黄色小框，写着"暂时无法获取额度"。
- **重置时间已过**：该额度显示 100% 和"已重置，正在刷新…"，直到读到新数据；另一个额度不受影响。
- **登录失效**（服务器不再接受这个账号的登录信息，或者它的登录 Cookie 已经没有了）：卡片显示"需要重新登录"，不再显示旧的数字。同一个登录信息不会每次都发给服务器：自动读取一小时最多再试一次，点刷新或者重新登录过（Cookie 变了）就立刻读。
- **claude.ai 拒绝读取**（返回的是网络中途的拦截页面，或者账号确认没问题、只是额度这一项被拒绝）：不当成退出登录，卡片写"claude.ai 拒绝了读取"，有旧数据就照常显示并标明是上次的。
- **请求太多**：claude.ai 说请求太多时（只是订阅渠道那一项也算，已读到的额度照常显示），这个账号在它要求的时间内不再读取（最长一天）；没说时间就先等 5 分钟，连续再遇到就加倍，最长 1 小时，读成功一次就恢复正常。期间打开面板、刷新、自动切换、登录检查都不读它，重启 CC-Relay 也不会提前，卡片写"请求太多，HH:mm 后再读"。
- **同一个文件夹换了账号**：在 Claude 里把某个账号文件夹改登成另一个账号时，之前那个账号的读取结果和"需要重新登录"都不会算到新账号头上，新账号按自己的情况重新读取。
- **组织信息不完整**：账号资料里找不到当前组织的记录时，只要这个账号只属于一个组织，就读那一个，照样显示额度、邮箱和套餐；切换时的对话同步仍会跳过这个账号。

## 九、自动压缩（设置里可开关，默认关闭）

- **为什么要压缩**：提示缓存按账号区分。一段很长的对话换到新账号继续，第一条消息要把整段对话重新算进新账号的额度。趁老账号还有额度、缓存还热的时候在老账号上压缩好，换账号后继续会省很多。以 80 万 tokens 的对话为例，新账号大约能省九成。
- **谁来压、在哪压**：装在 Claude Code 里的小插件"cc-relay"在每段 Claude 桌面端 Code 对话里实时看着当前账号的用量（每次回复、长任务的每一步都会更新），在**这个账号用完之前、在这个账号上**把对话压缩好。它不靠 CC-Relay 去网页读额度，CC-Relay 没开着也照样工作。本应用不操作 Claude 的窗口，也不模拟键盘。
- **两条线**：
  - **提前线**（剩余 12%，即用到 88%）：到线后，等 Claude 回完这一轮就压缩。
  - **保底线**（剩余 8%，即用到 92%）：到线时如果 Claude 还在执行很长的任务，就在两个步骤之间（上一步的工具已经执行完）暂停任务、压缩，然后自动发一句话让它从中断处接着做；压缩有没有成功记在面板提示和本地结果里，不写进这句话；这句话发不出去时，面板会提醒你自己让任务接着做。任务会停顿一两分钟。
  - **只会提前、不会推后**：插件会记住每次压缩实际花了多少额度，并留意用量在短时间内（前后两个读数相隔不到 2 分钟）一下涨了多少。如果剩下的 12% 或 8% 留给压缩和下一步的余量不够，两条线会自动提前（提前线最早到用到 75%，保底线最早到 85%），保证压缩在老账号用完前完成。这种跳动只算 30 分钟，之后两条线回到剩余 12% 和 8%；电脑睡眠或对话闲着期间别处用掉的额度，不算一下涨的。只有对话特别长、压缩本身就很费额度时，两条线才会一直早一些。无论如何都不会晚于剩余 12% 和 8%。用量到 99% 不再开始压缩。5 小时和每周额度哪个先接近用完，就按哪个算。
- **压哪些对话**：当前账号里最近一小时用过、有 10 万 tokens 以上的 Code 对话。一轮里一直在调用工具的长任务算一直在用，跑多久都算。几段同时到线时一段一段来，最近用的先压。每段对话每个额度周期最多压一次；没成功时最多再试两次，/compact 过了 15 分钟还没做完就不再等。排队等别的对话压完时，如果情况变了（开关关了、额度周期重置了、用量不再过线），就不压了，被暂停的任务直接接着做；排队期间你开始了新任务，这次提前压缩就先让开，等这一轮做完再压，这一轮里到 92% 照样会暂停压缩；同一段对话上一次 /compact 还没结束时，不会再发第二次。被暂停的任务无论压缩成没成功都会接着做，压缩被别的插件拦下时也一样。
- **压缩时不加说明**：插件只发一条 `/compact`，后面不加任何文字，对话里看到的就是一条 `/compact`。Claude 自己的压缩本来就会保留任务的目标和进度、改过的文件、做过的决定、没做完的事和你说过的话。
- **切换前**：切换时要带走的对话有 30 万 tokens 以上，本应用会请插件先在当前账号上压缩它（见第三节第 3 步）。这次压缩不看用量到没到线，这个额度周期里压过也照样压；开关、10 万 tokens 下限、最近一小时用过、没有任务在跑、用量不到 99% 这几条仍然要满足，不满足时插件马上回答压不了，切换随即继续。别的对话正在压缩时，它会等到切换不再等它为止；等到以后先把这几条再核对一遍，比如等的时候用量到了 99%，就不压了。
- **试压**：想不等到 88% 就看一遍完整的自动压缩，可以在 CC-Relay 的 `AutoCompact` 文件夹里放一个只对某段对话有效的试压请求（`test-request.json`，格式见 `docs/low-quota-compaction.md`），把它的提前线临时降到 0，其他规则都不变。挑一段不重要、但有 10 万 tokens 以上的对话（太短的平时也不压）。插件会按平时的流程自己判断、自己压缩，CC-Relay 面板也会像真的一样弹出提示，日志里记一行。10 分钟后请求失效，提前线回到原位；每个额度周期仍然最多压一次。
- **怎么压**：插件像你自己输入 `/compact` 一样执行压缩，Claude Code 会等对话空闲了再执行，你在对话里看到的也和手动压缩一样。
- **你能看到什么**：
  - 压缩后，打开面板时中间弹出一条提示，例如"已在额度用完前压缩对话：约 81 万 → 7 万"；长任务被暂停过的，会写"已暂停任务并压缩对话……任务已自动继续"；切换前压缩的，写"切换前已压缩对话：约 40 万 → 3 万"，切换后再打开面板时还能看到；任务被暂停后没能自动继续的，会提醒"任务没能自动继续，请让它接着做"（压缩没成功时，先请你手动发送 /compact）；没成功的，会提醒你手动发送 /compact（切换前没压成的不弹这条，由切换结果说明）。面板打开看过、再关上后，提示就消失；点"知道了"也可以先收起。
  - 日志里每次压缩记一行，以 `Auto-compact` 开头；没压缩成的，行尾会写 Claude Code 给的原因（英文，`Reason: …`）。
  - 设置里开关下面一行显示插件状态，前面一个小圆点："压缩插件已连接"（绿点一呼一吸，最近两分钟有对话在报到）、"压缩插件上次报到 HH:mm"或"还没收到压缩插件的报到"（黄点）；关掉开关时是灰点和"已关闭，不会自动压缩"。
- **关掉开关**：开关写在 `AutoCompact/settings.json` 里，压缩模块每次检查前、暂停长任务前都会重新读，关掉后停止自动压缩。同一插件的原生续接按第三节的规则运行。
- **压缩报告只有数字，没有内容**：压缩模块写给 CC-Relay 的只有对话大小、用量百分比、时间和结果；压缩没成时，再加一句 Claude Code 给的简短原因。原生续接保存的任务和证据位置见第十二节。
- **限制**：
  - 依赖 Claude Code 的插件功能。Anthropic 可能远程关闭或修改它；真被关掉，设置里会显示插件没在报到，这时需要你在额度用完前手动发送 `/compact`。
  - 只对 Claude 桌面端的 Code 对话有效，终端里的 `claude` 不管。
  - 压缩本身要花一点额度，所以一定要提前做；用完以后就压不了了。
  - 暂停长任务时，正在后台运行的命令可能会被一并停下。
- **安装**：这一个插件同时负责自动压缩和原生续接，就放在本应用里。插件还没装时，在设置里打开"自动切换"或"自动压缩"，面板中间会先弹出"自动切换要用 CC-Relay 插件"（或"自动压缩要用……"）。点"安装并开启"：本应用用 Claude Desktop 为账号自带的 Claude Code 程序（找不到时用单独安装的）把插件装好，并在 `~/.claude/settings.json` 里打开插件需要的一项设置，改之前先把原文件复制一份放在旁边；确认装好后功能才打开。装不上时说明原因（没找到 Claude Code、设置文件用不了、安装没有完成），功能保持关闭，可以重试。插件装好了、但正赶上切换等操作而没能打开功能时，对话框写"插件已装好"和"但自动切换这次没打开 / 等当前操作结束后再打开一次"，开关保持关闭。点"取消"什么都不改。已经开着的会话要重新加载一次才会用上插件。从源码开发时也可以运行 `scripts/install-plugin.sh`（需要先把 `CLAUDE_CLI` 设为 Claude Code 程序的路径）。
- **更新**：装了新版 CC-Relay 后，它一启动就用同一个 Claude Code 程序把插件更新到新版；插件来源指向别的位置时，先指回本应用里的这一份。平时什么都不显示。只有更新没成功时，设置的"切换"里多出一行"插件没能更新"，点"重试"再更新一次，成功后这一行消失。
- **彻底卸载**：只想停用自动压缩，关掉本应用设置里的压缩开关即可。要卸载整个插件，用 Claude Code 程序执行 `plugin uninstall cc-relay@cc-relay-local` 和 `plugin marketplace remove cc-relay-local`；这也会移除原生续接。确认其他插件不再需要函数 hooks 后，才删除 `~/.claude/settings.json` 里 `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` 这一行。安装时留下的备份是安装前的设置，直接拿它覆盖会丢掉之后在 Claude Code 里改过的设置。

## 十、设置

设置页顶部是"返回"和居中的"设置"，这两处是带棕色描边的艺术字（"返回"淡紫色，和它的箭头一样；"设置"蜜桃色）；下面分组，组名是靠左的灰色小字，每行前面有一个彩色小方块图标，下面一行小字说明这项做什么；有开关的行点整行任何地方都能切换：

- **外观**：跟随系统 / 浅色 / 深色，面板马上换过去，选中的一格滑过去。
- **语言**：跟随系统 / 简体中文 / English。
- **通用**：开机自启（登录 Mac 后自动打开 CC-Relay），默认关闭。
- **切换**：切换确认（点账号切换前先问一次，默认开启）；自动切换（默认关闭，开启后当前账号额度耗尽或实际限流时自动换号并续跑，无需切换确认或任务守卫确认；没有任务在跑时也换，下一句话直接用新账号，你停止了的回复不会被接着做；面板只在换不了时写明原因：没有可用账号时写几点后自动重试，其他账号都没登录时写登录后自动重试，别的账号的 Claude 也开着时请先关掉它，没能准备好接续时写几点后再试；有需要授权才运行的命令在跑时等它结束再换，不提示；刚因限流报错换过号，新账号 10 分钟内又报限流、额度还有余量时不再换，写"刚换过号又遇到限流，先不再换"，这段会话停在报错上，等你回去继续；限流信号结束或会话恢复正常回复后提示消失，额度确认用完时照常换；Claude 报错说账号被暂停或所在组织不允许使用时，不管额度和限流怎么显示都不再自动换号，写"这个账号被暂停或不允许使用"，这段会话留在原账号；会话恢复正常回复或满一天后提示消失，手动切换不受影响）；自动同步（切换前先备份，再同步两个账号的对话记录；自动切换总会同步）。
- **压缩**：自动压缩（额度快用完时，先把很长的对话压缩，默认关闭），下面一行是插件状态（见第九节）。
- 插件还没装时，打开"自动切换"或"自动压缩"都会先问是否安装插件（见第九节）。
- **已忽略的账号**：有时才显示，每个后面有"重新添加"。
- **其他**：打开备份文件夹（每个账号保留最近 5 份备份，打开后面板中间浮出"已在访达中打开备份文件夹"）；退出 CC-Relay（红字，点了先在下面问一句"退出后额度不再刷新，也不会自动切换账号。"，选"退出"才退出）。
- 最下面是版本号，点一下就复制，面板中间浮出"已复制版本号"。版本号后面的括号里是这个版本对应的代码版本（例如"版本 0.1.0 (5d42a6f)"），后面带"+"的是用还没提交的改动（包括新建还没提交的文件）构建的；每次安装的都能这样分辨。

默认启动纠正始终开启，设置里没有它的开关。有操作进行中时，开关和语言暂时不可改，外观随时可改。

## 十一、退出本应用

如果退出时正在切换账号或导入历史，会等操作做完再退出（正常只要几秒到一两分钟，最多等 3 分钟），不会在它往账号文件夹里写对话记录时就把 Claude 打开。还在等任务结束、或者还在等对话先压缩的切换（这时 Claude 还没被关闭），会直接取消，Claude 保持原样。等了 3 分钟操作还没做完时，它正在写入的那个账号先不打开（免得 Claude 和它同时写同一批文件），等下次打开本应用时再补开，其他账号照常打开。退出前会按磁盘上的记录把需要重新打开的账号打开，保证不会把你留在"Claude 被关掉、却没有重新打开"的状态。

## 十二、隐私与安全

- 菜单栏应用直接访问的网络接口只有上面三个 claude.ai 接口；没有统计、没有自动更新、没有额外服务。插件在 Claude Code 内执行压缩和续跑，会使用当前账号的额度、已有工具权限和工具自身的网络访问。
- 不保存、不记录 Cookie、会话密钥和令牌。日志里的邮箱会打码（例如 `d•••@example.com`）。
- 每次切换（包括"自动切回"）都在日志里记一行结果：从哪个账号到哪个账号（只记文件夹名，例如 `Claude_205`）、成功还是失败和失败原因、用时。等任务结束、等对话先压缩花的时间单独写，不算进切换用时；关不掉 Claude 时会写出没退出的程序名和原因：关闭途中 Claude 又被打开了、有 Code 任务在跑所以没有强制退出、强制退出后仍在运行，或者关闭超时。点当前账号自己的卡片不算切换，不记。
- 每次启动在日志里记一行"Started version …"，写明启动的是哪个版本。
- 数据都在 `~/Library/Application Support/CC-Relay/`：`state.json`（账号列表与设置）、`quota-cache.json`（最近一次额度）、`quota-waits.json`（claude.ai 要求的等待）、`AutoCompact/`（第九节：压缩开关、报到和结果）、`NativeRecovery/`（原会话和任务 ID、历史证据位置、进程身份及续接回执）、`Backups/`、`Archive/`、`Logs/`（日志，单个文件超过 1 MB 自动轮换）。原生续接会读取原会话的结构化历史，但快照不复制完整命令和消息正文；原始正文继续留在 Claude 自己的记录里。
- 托管的后台命令，其说明、输出和交接记录在只有你自己能读写的 `/private/tmp/cc-relay-native-<编号>/` 下；shell 函数和别名的临时文件读完即删。命令结束三天后，它的记录和输出会被删除；一天没报到的状态文件、一周前的续接记录也会清理；还在运行的命令不会被清理。
- 原生续接不会复制登录凭据、改变工具权限或替新账号取得旧账号私有资源的访问权。
- 开机启动用系统自己的登录项，在"系统设置 → 通用 → 登录项"里以 CC-Relay 的名字出现。你在那里关掉它，就保持关掉；系统因为别的原因不接受时，改用 `~/Library/LaunchAgents/local.cc-relay.plist`，下次登录生效。

## 十三、目前不包含

命令行工具、自动更新、手动同步会话、全局快捷键、系统通知、合并重复账号、导出诊断信息。
