# 原生工作续接

切换账号必须关闭原来的 Claude Desktop，它的 Code 进程和这些进程正在做的事都会随之结束。原生工作续接让目标账号打开后，原来的会话在原处接着做没做完的工作：用户继续使用原有的 Bash、Monitor、Agent 和 Artifact 工具，不用改用另一套任务工具，也不用把任务重新描述一遍。

续接依据的是已经保存的会话历史、任务结果、输出和检查点，以及切换前就交给独立执行程序的后台命令。它不迁移任意程序的内存，也不重跑无法核验的旧命令。打开会话、提交续跑提示、工具真正执行和原任务完成，是分别记录的四件事。

## 启用条件

- 手动切换时 CC-Relay 设置中的"自动同步"开启（自动切换总会同步），源账号与目标账号的身份及组织信息可以核验。
- 源账号和目标账号的会话都加载了 `cc-relay` 插件的当前版本，插件目录里带有配套的 `CompanionNativeWorker`。同一插件也负责自动压缩，压缩开关只控制压缩。
- 后台命令须在插件加载之后启动，才能受托管；之前就在运行的命令无法追溯接管。
- CC-Relay 只向报告 `native-recovery-v6` 能力的插件放行，请求也带着同一要求；执行程序须是协议 3。更早的插件或执行程序不会被当成兼容。

安装用这个脚本：

```bash
CLAUDE_CLI=/absolute/path/to/claude scripts/install-plugin.sh
```

从源码安装时，脚本会构建执行程序并放进暂存的插件目录；应用自带的插件目录已经包含签好名的执行程序。已经打开的会话须重新加载插件后，才具有这些能力。

## 自动触发

在设置开启“自动切换”后，以下两个信号可自动发起切换：源会话报告五小时或每周额度达到 100%，
或宿主的 `classic.StopFailure` 事件明确给出 `error: rate_limit`。两分钟内、身份一致的成功网络额度读数
也能触发；过期缓存、重置时间预测、认证失败、网络错误和服务器繁忙不能触发。插件会话的报告仍须由
CC-Relay 核对实际进程与账号，用户主动停止的会话不参与自动切换。

自动切换开启后最多每五秒检查报告。触发后同时重新读取已登记账号的额度，按面板推荐的规则选择五小时至少
剩余 10%、每周仍有额度的账号，每周额度剩不到 5% 的排到最后，排除同一登录身份和最近失败的目标。没有可用账号时保持 Claude 原状，
其他账号要等最早可能能用的那一刻才再读：卡住它的额度窗口重置，或它的十分钟排除期结束；读数说明不了时按
十分钟算。账号有增减或某个账号的登录有变、重新打开自动切换，或定时刷新带来的新读数已显示有账号可用时，立即再读。
目标账号打不开或登录不符时，十分钟内不再自动选它，三十秒后改试别的账号；
其他原因的失败换哪个账号都一样，就等十分钟再试，其中原任务没能准备好续接时只显示暂停说明，不弹切换失败；换号成功以后，新账号不再等这十分钟，半分钟后照常检查。
没有会话报告限流时，只有两分钟内的额度读数显示已用完才往下检查；读数有余量就撤下暂停说明，
读数较旧则什么也不判断，检查本身也不为此联网读取额度，等定时刷新带来新读数。检查只读各会话的报告，
不读会话历史。无重置时间的实际限流错误保留十分钟，
成功完成新回合或用户停止会撤回这个信号，之后仍可由新限流事件或有效额度读数重新触发。
一次只靠限流错误、额度读数并未用完的自动切换成功之后，新账号在切换开始后十分钟内自己又报限流时，先单独读一次这个账号：读数新鲜且还有余量，就不再切换，下一个账号多半一样，Claude 只会再关一次。这个判断在准备交接之前做，不碰取消流程；面板写明原因，这段会话停在报错上等用户回来，这期间不再读别的账号。信号到期或被撤回后提示消失；读数显示用完、读不到新鲜读数，或已过十分钟，都照常切换。
会话的回合因账号被暂停（`account_on_hold`）或组织不允许（`oauth_org_not_allowed`）而失败时，插件在报告里写明，这一项比限流错误和额度读数都优先：原账号任何一段会话这样报告，自动切换就停下，不读别的账号，也不关 Claude，面板写明原因。这段会话成功完成新回合后撤回，用户停止回复不撤回，最长保留一天。关闭 Claude 前的最后一次核对同样会拦下。手动切换不受影响。

自动切换跳过手动切换确认、任务守卫提问和切换前压缩：已用完额度的任务无法先压缩或正常完成。
开启自动切换代表允许这种自动交接，也总会同步对话记录，不看"自动同步"开关。额度用完、有别的账号可换时就换：
会话都已做完、你停止了回复、会话没有报告，或会话历史读不通、太大，都不挡换号。没做完的会话换过去后照样接着做；
历史读不通或太大时，续接回执标明分支未核验，插件不重放其中的任务，由会话按自己的历史判断做到哪一步。你停止的回复不会被接着做。
受托管的后台命令随会话带过去；需要授权才运行的后台 Bash 命令没有托管，换号会让它随 Claude 停止，
所以自动切换先等它结束，面板不为此提示。另一个账号的 Claude 也开着时保留原账号并说明原因。续接文件写不下来时等十分钟再试。网页（Artifact）评论监听
不挡自动切换：网页属于发布它的账号，只挂着监听的会话留在原账号，不在目标账号打开（见下文“留在原账号的评论监听”）。
升级不会自动打开此开关。

插件还会在每轮对话结束时（公开的 `Stop` / `SubagentStop` 事件）记下 Claude 列出的后台任务，补上它自己没看到启动的命令。
只记任务 ID、类型和状态，最多 128 项，不记命令和描述；已结束或已停止的任务从清单里去掉，之后也不再记回。
额度用完时只有本机上在跑的命令还能继续，关掉 Claude 会把它掐断，所以只有清单里插件没保护的命令会让自动切换等它结束，
也包括已停止回复的旁观会话；手动切换照常进行，但提示续接不可用。子代理、定时唤醒、评论监听等要靠模型的工作在额度用完的账号上本来也动不了，
不因它们暂停。没有清单时沿用原来的核验。

自动切换只换到能接着做的账号：要接着做的会话里有处在“跳过权限确认”模式的，目标账号的 Claude 也必须
允许跳过（它的 Desktop 配置里，这个账号的资格和选择都已打开），否则在关闭任何东西之前改选别的账号；
会话记录读不出模式时不做这项限制。
有额度的账号都不允许时保留原账号，提示写明可以到哪个账号手动打开。手动切换不做这项限制：
用户在场，可以在目标账号里处理权限确认。

自动切换关闭源账号后，如果备份或同步失败、原会话在关闭后找不到，或续接记录存不下来，会取消这批续接，重开原账号和原会话，
不再启动目标；已经同步成功的文件不反向覆盖。原因多半还在，所以在这个账号的额度恢复前（至少十分钟）
不再从它自动切换，面板显示暂停原因；关闭再打开自动切换即重新允许尝试，手动切换不受影响。
重开失败时保留原账号的待重开记录；重开成功只确认账号已打开，任务状态仍须查看原会话。
手动切换遇到同样的失败时照常完成切换，并提示续接不可用。

## 切换时发生什么

1. **关闭前记下工作。** 任务守卫选择和必要的压缩完成后，枚举原账号所有正在运行的 Code 会话，并行读取它们的会话历史，记下未完成的主回合、后台命令、监听、子代理和 Artifact 评论订阅的证据位置，同时读取插件报告的实时任务清单。没有工作的空闲会话保持关闭，只挂着网页评论订阅的也一样：网页属于发布它的账号，目标账号打不开它。有工作的会话照常续接，它的评论订阅同样留在原账号。
2. **关闭前后各核对一次。** 真正关闭前再次核对用户是否主动停止；关闭后接着上一次读到的位置读完 Claude 刚保存的内容，不再从头读。已经完成的工作改为已核对；关闭后读到的历史接不成完整的一条时，按无法核对处理，不当作已经做完。关闭造成的中断不算用户主动停止。
3. **先同步，后放行。** 请求先保存为未就绪；源账号关闭、备份和同步都成功、目标账号已经启动后，才允许目标会话认领。任何一步失败都会取消这批请求；目标打不开而退回源账号时，改为向重新核验后的源账号续接。一次切换接过了上一次还没被认领的工作，又在关闭 Claude 之前取消时，上一次的请求和命令许可原样恢复，接着等它的目标会话认领。启动目标账号之前，给这批要续接的会话记录写上 Desktop 自己的"退出时正在工作"标记，让 Desktop 一启动就运行它们的 CLI；正在等用户处理或已被用户停下的会话不写。自动切换时要么全部写上，要么一个都不留：有一段写不上，已写的恢复原样，回到原账号。Desktop 随后发出的那句"接着做"由插件处理：有续跑时让给续跑，不需要模型回合的会话直接拦下。
4. **确认新运行时。** 目标会话的 Desktop 会话 ID 和 CLI 会话 ID 必须与原来相同。CC-Relay 自己核对进程的 PID、出生时间、可执行文件、父进程链、Claude 会话登记和目标资料目录的账号与组织；插件自报的身份不算数。认领之后，只要这个进程还活着，续接就有效，Mac 睡眠或宿主一时繁忙不会使它失效。
5. **打开其他会话。** 切换时正在看的会话由启动链接直接打开。其他还有工作的会话逐个打开，打开方式见下文。
6. **直接接回具体工作。** 插件把认领回执写入并读回确认后，先接回受托管的后台命令和监听，按剩余时限重建 WebSocket 监听，用原编号续接被打断的子代理，再检查原网页的评论订阅。
7. **最后提交续跑提示。** 主会话收到不含项目名称的 `[Continuation requestID=…]` 标记，以及一句英文："Please continue the unfinished work from where it was interrupted, following the original instructions and scope of authorization." Claude 根据原会话历史继续没做完的部分。完整工作快照和恢复证据保存在本地请求与回执中，不再附进提示。这条提示负责后续工作，不负责重跑已接回的命令。

## 留在原账号的评论监听

网页评论监听留在发布网页的账号，别的账号打不开那个网页。只挂着监听的会话留在原账号；有工作的会话照常到目标账号接着做，它的监听同样记在原账号名下。换号后面板提示监听留在了哪个账号，并列出这些会话的标题。目标账号上的插件不去连这些网页，也不因此报接续受阻；监听的账号归属保存在本地，续跑回合里对它们的监听调用会被拦下。之后在别的账号普通重开这段会话，也不去连这些网页。

已经记在某个账号名下的网页不改记到别处：会话再被带到第三个账号，监听仍等发布网页的那个账号；那个账号打开过以后也一样。记录按会话列出网页（`pages`）；较早的记录没有网页列表，算作这段会话的全部监听。

CC-Relay 下次打开这个账号时（切回它，或换号失败回到它），先给这些会话写上 Desktop 自己的"退出时正在工作"标记，让 Desktop 一启动就运行它们的 CLI，再在 `NativeRecovery/watch-reopen/<CLI 会话 ID>.json` 留一张写明账号的一次性便条。插件在会话启动时用掉便条（认出自己开在别的账号上时不用，留给便条写明的账号），拦下 Desktop 随后两分钟内发出的那句"接着做"，不开始模型回合；监听由下文普通重开的恢复接回，结果照常在原会话提示。这次打开要接着做的会话不在此列：它们随续接在这个账号上接回监听。

CC-Relay 发现一个账号已经开着、不是它为监听打开的（当前账号，或别的工具指定这个账号打开、和当前账号同时开着的）时，Desktop 已经不能再被告知启动这些会话：哪段会话在这个账号里被打开，哪段就照常接回自己的监听。

这两种情况下记录都不删除，只标为已打开（`opened`）：面板不再提示，CC-Relay 也不再为它们启动会话，记录只用来说明这些网页属于哪个账号，满一周作废。普通重开时，插件只接回自己所在账号名下的网页，别的账号名下的照样不连。插件这样认出自己的账号：CC-Relay 为监听启动的会话，便条上写着账号；其他会话查 `NativeRecovery/open-accounts.json`，CC-Relay 每次扫描时在这里写下每个开着的 Claude 的进程号、启动时间（UTC，精确到秒，和 `ps` 显示的一样）和所在账号，插件顺着自己的上级进程找到所在的那个 Claude。查不到账号时，留在任何账号名下的网页先不连，其余监听照常接回；CC-Relay 五分钟内会列出开着的 Claude，所以插件每 30 秒再查一次，最多 6 分钟，查到是自己账号的网页就接回，不重读历史。

只有插件报告了 `watch-reopen-v1` 的会话才这样处理：较早的插件不会拦下那句"接着做"。记录按账号保存在 `NativeRecovery/left-watches/<账号文件夹>.json`，最多保留一周；打开失败时记录留到下一次，便条收回，不留给别处的启动。

## 各类工作

| 工作 | 续接方式 | 要分开看待的结果 |
|---|---|---|
| 主会话 | 自动提交简短英文续跑提示，Claude 根据原会话历史继续。 | 提示被接收、回合开始、工具返回、原任务完成。 |
| 子代理 | 核对原 ID、历史和状态，对被这次切换打断的子代理用 `SendMessage` 以原 ID 续接。 | 消息被接收、子代理真正执行、回合结束。已完成、主动停止、在等用户输入、历史不可读的子代理不会被新建的代理替代。 |
| 受托管的后台命令和命令监听 | 新账号的原生 Bash 或 Monitor 接上同一个进程和它的输出；命令监听用字节游标只补发尚未交出的输出。 | 命令仍在运行、已完成、非零退出、已停止、执行程序丢失。旧命令不会再执行一次。接上之后命令自己结束、失败或被停止，是命令本身的结果，不算续接出了问题。 |
| 未受托管的后台命令 | 换号时随 Claude 停止；本地续接回执记为 interrupted，由 Claude 根据原历史和输出决定是否重启。 | 是否重启及原因。 |
| WebSocket 监听 | 插件从原调用里读到唯一可核验的参数，按剩余时限直接重建。会话压缩过、原调用已不在当前历史里时，执行程序从完整的原始记录中按原会话、活动分支、调用和任务 ID 找回参数，只在内存中交给插件。 | 新监听已创建与收到真实事件分开记录；中断期间的消息需要对方服务支持补读。 |
| Artifact 评论订阅与自动回复 | 网页属于发布它的账号，新账号打不开它：订阅留在原账号，目标账号不去连接，也不因此报接续受阻；只挂着订阅的空闲会话也不打开。原账号下次打开时，空闲的会话为监听重新启动，续接过来的会话随续接接回。同一账号里重开时，检查原网址的订阅状态；原来启用了自动回复时，按需用一次普通 `ArtifactComments watch` 重新挂接，由宿主检查用户回合、用户提供的链接、原授权及编辑权限，并再次查询。 | 连接和自动回复分别确认；仅连接成功不改变原有回复意图。纯监听仅在库存明确显示已连接且 `auto_reply: none` 时确认；需要新建而宿主无法保证不启用回复时标为待处理。主动停止或宿主拒绝时保留具体原因。`resume_replies` 只能恢复已记录的停止，不用于补接 `auto_reply: none`。 |

普通重开会话也执行同一套 Artifact 恢复，不依赖换号请求。插件先给宿主十秒自行恢复，再由执行程序流式读取原会话唯一的完整记录；压缩过、记录超过 hook 的单次读取上限时，仍能读取原生 `artifact-comment-monitor` 意图。分叉出来的会话，按 Desktop 记录里写明的来源会话接上分支，和换号时一样。仅发布过网页、在文字中提到链接，不会被当成监听授权。正在运行普通回合时先等到空闲；恢复过程中用户发新指令或按停止，恢复让位。已完成握手且自动回复已启用时，不再重复注册；正在连接时最多做六次间隔十秒的查询。宿主可能同时返回 `connected: true` 和 `connecting: true`，此时握手尚未完成，纯监听与自动回复都保持等待，`repliesReady` 为假；握手完成后才确认，六次仍未完成则标为待处理并保留原因。普通重开的结果保存在 `NativeRecovery/artifacts/<sessionID>/<instanceID>.json`，需要处理时在原会话提示。自动回复仍走宿主权限检查；被拒绝时不通过重新发布网页或伪造用户消息绕过它。

压缩后的合法保留片段也能恢复 Artifact 意图：当保留片段已经重新挂在新摘要下面，旧的逻辑父指针可能指回这个片段。读取器只在完整保留片段、摘要身份和物理父链都相符时去掉这条过时逻辑回边，不再把它误判为真实环；同 UUID 重写采用最新记录，增量读取也会重新判定。真正的环、缺失父节点、错误或不完整元数据仍会阻止自动恢复；较新的停止记录优先于较旧的启用记录。恢复继续对原 URL 使用 `watch`，不会重新发布网页或放宽宿主权限。

当前宿主的普通 `watch` 可能因已有授权而隐式启用自动回复，`replies: false` 不提供强制纯监听的保证。因此纯监听需要新建、或已有监听的回复状态无法确认为 `none` 时，恢复只读检查并记录待处理，不擅自挂回复，也不更改现有回复者。已经确认的纯监听不受仅针对回复的权限或启用条件阻挡；正在连接的纯监听按同样节奏等待库存确认。

首次读取原记录失败时，每十秒重试，最多三次；期间保留等待回执，耗尽后记录实际错误并提示一次。只有确认原历史不存在的新会话保持安静；目录列举、项目目录查找或文件读取被拒绝时返回权限错误，进入同一重试和提示路径。`auto_reply: none` 只说明当前运行时没有挂上回复，不会清除之前保存的回复恢复意图；显式停止或原生停止记录才会清除它。

## 后台命令的托管

续跑提示、自动回合识别、工具执行及原命令权限检查使用宿主提供的 hook 失败处理。
关键提示或工具检查在执行前抛错、超时或返回无效结果时，本次操作被拒绝；已经进入后续执行时，保留宿主缓存的
结果，不重新排队或重跑命令。自动回合的身份检查失败时只阻挡已签发的自动续跑，并立即把这次续接记为接续受阻（它不会再被接回）；后来的普通用户回合不继承该身份。
运行时报告中的 `hookFailure` 只记最近失败的事件和类别，不复制原异常中的命令或消息；这条历史诊断本身不会永久禁用后续手动操作。
宿主的错误处理器也有自己的执行限制，因此仍须保留独立的进程、许可和回执检查，不能把注册了处理器当作任务恢复成功。

只有当前权限规则或模式会直接放行的后台命令，才交给执行程序托管；"跳过授权"模式下一般就是全部后台命令。需要用户点授权的命令，以及设置里存在任何 PreToolUse 钩子时的所有命令，都照原样运行：授权弹窗、自动模式的安全检查和钩子看到的都是真实命令，这些命令在切换时会停止。

受托管的命令：

- **授权不变。** 判断依据始终是原命令；托管用的包装命令既不会多弹一次授权，也不能绕过原命令的拒绝。包装命令被规则拒绝时照样拒绝。启动前原命令已经需要询问时，不再启动；切换后在新账号里需要询问时，执行程序会被停止，而不是挂在一个可能没人回答的弹窗上。
- **环境不变。** 原生 shell 把自己的函数和别名写进本任务的私有目录，执行程序用同一种 shell 载入后立即删除；工作目录、导出的环境变量和原生 shell 的沙箱都原样继承。任务列表仍显示原命令的第一行。
- **只执行一次。** 启动前写下一次性记录；记录丢失也不会再执行同一任务。
- **停止可靠。** 从界面或 `TaskStop` 停止、或原会话退出又没有交接许可时，执行程序结束整个进程组：先请它退出，最多等半秒，再强制结束，直到连续两次都看不到组里还有进程，连命令正要启动的进程也不会漏掉；无法确认停止时明确标为待处理。
- **不占资源。** 执行程序和输出客户端只在文件、进程状态或时限变化时醒来，命令空闲时不占用 CPU。

## 其他会话的打开

除切换时正在看的那段，还有工作的会话由 CC-Relay 逐个打开：把会话链接交给系统，由系统转给目标账号的 Claude。这样做不需要任何自动化授权，也不会启动另一份 Claude。只有当目标账号的 Claude 是唯一在运行的 Claude 时才这样做；同时开着别的账号的 Claude 时，系统可能把链接交给别的窗口，这几段会话标为待处理，需要手动打开。

每段会话最多等 30 秒，等它的新运行时连上再处理下一段；整批自动打开的时间按会话数量在 90 到 300 秒之间。最后只尝试一次回到切换前正在看的会话。之后手动打开原会话，在请求的 24 小时有效期内仍可完成认领和续接。

## 时限

- **交接许可。** 受托管的命令在原 Claude 退出后能继续运行，靠的是一张交接许可。许可在 Claude 真正关闭后签发，有效 300 秒；会话还没在目标账号打开时，CC-Relay 会在许可快到期时续期，最长到自动打开阶段结束后再多 300 秒。目标会话接手之后许可不再续期，以后这段会话退出时命令照常结束。没有人接手的命令在许可到期时被结束，不会在后台无人看管地运行。命令的记录找不到或对不上、发不出许可时，自动切换不关闭 Claude，保留原账号并说明原因；手动切换照常进行，并提示有工作没能接续。
- **轮询节奏。** 切换后的 15 分钟内，CC-Relay 每 2 秒检查一次；之后每 30 秒一次，以便手动打开的会话仍能被认领；所有请求都有最终结果后停止检查。
- **请求有效期。** 24 小时内可以开始新的续接动作；已有的最终回执在过期后仍然保留。

## 防止重复和误恢复

- **完成与主动停止优先。** 明确完成、`TaskStop`、停止评论订阅和用户主动中止，都不会被更旧的通知覆盖，也不会被续跑顺带复活。
- **命令结束后也不重跑。** 自动续跑的回合再次请求同一条原命令时，无论执行程序已完成还是失败都会拦下。
- **用户优先。** 换号后用户发出新消息，或在续跑中按下停止，自动续跑即让给用户；已派出的自动回合的工具资格被撤销，即使取消回合失败也一样。续跑的回合还在进行时用户发话，这一回合立即停下，用户的话在自己的回合里执行，工具不受限制；按回车、用 ctrl+x 回车排队发的消息和斜杠命令都一样。续跑已经结束之后的新消息或停止不改变它的结果，子代理此后被拦下的工具也不改变；还在等连接的评论订阅不再等，回执按回合本身的结果定下。
- **Claude 自己的"接着做"让给续跑。** 回复进行中被切换关掉的会话，Claude 重新打开后会自己发一句 "The app was quit while you were working. Please continue from where you left off."。插件按意思认这句话：大小写、标点、近义的说法（closed、restarted、resume、pick up 等）或两句前后调换都还算；多了别的内容就当是用户的话。这句不算用户的话；本次切换的续跑正在赶来时先把它扣下，由续跑代替，只续跑一次，接回的命令、代理照常接回。两分钟内没有续跑认领、或者续跑不需要发提示时，再把这句原样发出；之后才认领的续跑让位。
- **认得出自己的回合。** 宿主会在插件提交的提示、以及发给子代理的消息前面加一行署名；自动回合仍按署名之后的本次请求标记认出。用户自己的话里引用了这个标记，不会被当成自动回合。
- **步骤失败属于工作本身。** 续跑中某一步失败（比如测试没通过）只记为一条证据；回合结束时动过的工具全部失败，才报待处理。只用文字把回复写完、没有调用工具的回合也算执行过。
- **代次与实例绑定。** 每个请求只对当前切换、原会话、目标账号和核验过的插件实例有效；快速连续切换时旧请求失效。认领后的进程绑定只写一次，不会被另一个更新的运行时抢走。
- **历史只是数据。** 只采信活动分支中的原生结构和宿主标记的事件；形似任务通知的普通文字不能证明完成或授权续跑。
- **不猜缺失信息。** 分支不完整、原调用无法核验、代理历史不可读或资源缺失时，记录原因交给原会话处理，不构造新参数，不从头重做。
- **简短的提示。** 主会话只收到本次请求标记和一句英文续跑指令；完整任务、网页及恢复证据保存在本地请求与回执中，不随任务数量增长而扩展提示正文。

## 面板状态

| 面板文字 | 记录的事实 | 不代表什么 |
|---|---|---|
| 正在接续 | 还有会话在等新账号上的运行时，或续跑提示已提交、正在执行。目标账号打开后的头 30 秒里，有问题也先这样显示：那里的会话大约要半分钟才报到。 | 工具已经执行。 |
| 接续成功 | 每段会话的续跑回合都已结束（只用文字把回复写完也算），或工作在关闭期间已经完成、只需核对。 | 原任务已经完成，或每个订阅都已连接。 |
| 接续受阻 | 过期、无法自动打开、记录异常、权限或任务状态不允许，或续跑的回合结束时动过的工具全部失败。 | 系统会无限重试。 |
| 切换时结束了 N 个后台命令 | 切换前用户停下了回复，它启动的受保护后台命令当时还在运行，切换时随之结束。普通提示，不是警告；有别的状态时列在它下面。 | 命令出了错。 |

“正在接续”和“接续成功”的第二行写明从哪个账号换到哪个账号；两个名字一行放不下时只写换到的账号，失败后回到原账号时不写这一行。本文其余地方记为“待处理”的情况，面板上都显示为“接续受阻”。

用户自己决定的事不算问题：切换前停下的回复、换号后发新消息或按停止接手的续跑（回执为 `yielded`）、自己停掉的接回任务，都不计入面板。停下的回复没有许可带过切换，它留下的受保护后台命令会随切换结束；自己结束或在切换开始前已停的不算，其余按“切换时结束了 N 个后台命令”告诉用户，是否重跑由用户决定。一次切换里只有这些时，面板只出现这一项普通提示，或者什么都不出现。

状态变了提示会重新出现。全部结束、用户在面板里看过之后，面板关闭时提示消失；目标账号打开后的头 30 秒里不算结束，好让这段时间里先压下的问题还能显示出来。

“接续受阻”后面只跟一句原因和下一步；原因不止一种时，改说有几段会话没能接续。各会话的完整原始错误保留在本地记录中。“查看本地记录”只打开 `NativeRecovery/` 文件夹，不启动账号扫描、历史导入或续跑。

换号后的头 30 秒里，新账号上的会话还没报到也不暂停自动切换；过了这段时间仍没有报到，才显示暂停提示。

## 本地数据、清理与隐私

数据位于 `~/Library/Application Support/CC-Relay/NativeRecovery/`：

- `active.json`：当前切换代次、目标账号、预期会话清单、自动打开时限和结束时间。
- `requests/<cli-session-id>.json`：原会话、任务 ID、状态、历史文件及行号等证据位置，以及绑定后的进程身份。
- `runtimes/<cli-session-id>/<instance-id>.json`：插件运行时的报告，须经 CC-Relay 独立核验。
- `results/<request-id>.json`：认领回执、进度、工具证据和错误。
- `locks/`：写请求和提交代次时用的短文件锁。
- `commands/<job-id>/location.json`：指向该命令的私有执行目录。
- `left-watches/<账号文件夹>.json`：留在这个账号的评论监听，按会话列出网页；这个账号打开后标为已打开，只用来说明网页属于哪个账号，满一周作废。
- `watch-reopen/<cli-session-id>.json`：为监听重新启动会话时留给插件的一次性便条，写明账号。
- `open-accounts.json`：每个开着的 Claude 的进程号、启动时间和所在账号，供插件认出自己的账号。

受托管命令的说明、进程身份、输出、游标和交接许可，位于只有本人能读写的 `/private/tmp/cc-relay-native-<uid>/<uuid>/<job-id>/`。命令参数只为这一次执行保存；环境只在内存中继承，不落盘。shell 函数和别名的文件在载入后立即删除。系统清掉临时目录或执行程序丢失时只报待处理，不会重跑命令。

清理在 CC-Relay 启动时和每次切换的续接全部结束时进行：一天没有报告的运行时记录、一周前其他切换的请求和回执、结束超过三天的命令记录及其执行目录和输出会被删除。执行程序仍在运行的命令无论多久都不会被清理。

快照不复制完整的命令或消息正文，原始历史仍在 `~/.claude/projects/`。续跑使用当前账号的额度和已有权限，不复制登录凭据，也不替新账号取得旧账号私有资源的访问权。命令和输出可能包含用户自己的敏感内容，与原任务输出一样属于本地私有数据。

## 已知限制

- 不关闭 Claude 就换号：官方接口不支持，插件既拿不到也换不了登录。
- 同时开着多个账号的 Claude 时，除正在看的会话外，其他会话需要手动打开。
- 需要授权才运行的后台命令不受托管：手动换号时会停止，由 Claude 判断是否重启；自动切换先等这类后台 Bash 结束再换。
- 新账号打不开的网页，评论订阅接不上。
- 换号期间 WebSocket 推送的消息，只有对方服务支持补读时才不会丢。
- 插件加载之前就在运行的命令，以及自己脱离进程组的后台进程，无法接管。

## 验证范围

完整本地入口为 `scripts/test-all.sh`，串起 Swift、Node 与插件宿主回归，并让 Node 使用同一次运行构建的执行程序。各阶段明确显示 PASS、FAIL 或 SKIP；构建失败时不会回退到旧执行程序。定向 Swift 验证继续使用 `scripts/test.sh --filter Name`。

插件的 `.test.ts` 在有 `claude` 命令时，用临时配置目录交给 Claude Code 自带的测试宿主运行（`claude plugin test`），没有该命令时列为 SKIP。它不安装插件、不重启应用、不切换真实账号、不发送真实评论。
