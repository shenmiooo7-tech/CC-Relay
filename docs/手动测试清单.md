# CC-Relay 手动测试清单

自动化测试只用模拟的 Claude（FakeClaude）和临时目录，从不碰你真实的 Claude、钥匙串、Cookie 和网络。`scripts/test-all.sh` 串起 Swift、Node 与 Claude Code 自带的插件测试，并明确列出跳过的项目；`scripts/test.sh --filter Name` 用于定向 Swift 测试。下面这些需要你在真机上亲自确认。

建议顺序：先做"一、沙盒体验"熟悉界面（完全不碰真实数据），再按"二、真机测试"从上到下进行，后面的项目风险更高。每项都写了"预期结果"，与预期不符时请记下现象和时间，日志在 `~/Library/Application Support/CC-Relay/Logs/cc-relay.log`。

## 一、沙盒体验（不碰真实数据）

沙盒是一个临时文件夹，里面有模拟的 Claude 和 4 个模拟账号。沙盒里的本应用只读写这个文件夹，不联网、不弹钥匙串，也不会碰你真实的 Claude。模拟的 Claude 没有窗口，只在后台运行；它的关闭和重新打开，从切换对话框的进度上就能看到。

**准备**

- 如果已经在用正式版本应用，先退出正式版（两者不能同时运行，否则沙盒版会直接退出）。
- 打开"终端"，进入项目文件夹（项目不在"文稿"里时，换成它实际的位置）：

```bash
cd ~/Documents/"CC-Relay"
```

- 生成沙盒并打开沙盒版本应用（第一次要编译几分钟）：

```bash
scripts/run-sandbox.sh "$TMPDIR/cc-relay-sandbox-1"
```

  **预期**：菜单栏出现本应用图标；这个终端窗口会一直被占用，退出本应用后才恢复。想从头再来时换一个新名字（`-2`、`-3`……），已经用过的文件夹不会被覆盖。

- 再开一个终端窗口，同样先进入项目文件夹，下面的控制命令都在这个窗口里执行。每条命令执行后会打印一行结果。

沙盒里的 4 个账号，以及控制命令里要用的文件夹名（第一次打开面板时，名字先显示为"默认账号"和文件夹后缀，读到邮箱后马上换成下面的名字）：

| 账号名 | 5 小时剩余 | 文件夹名 |
|---|---|---|
| ada（默认账号） | 90% | `Claude` |
| bob | 80% | `Claude_204` |
| cara | 70% | `Claude_Kxm2` |
| dax | 60% | `Claude_Kxm8` |

模拟数据里每个账号的套餐都是 Pro、每周剩余都是 58%，订阅渠道都是 App Store；5 小时额度在生成沙盒约 4 小时后重置，每周额度在 4 天后重置。

## 二、真机测试

### 0. 开始前

- [ ] 确认 Claude 桌面端在正常使用，记下 `~/Library/Application Support/` 里有几个 `Claude`、`Claude_xxx` 文件夹（每个是一个账号）。
- [ ] 安装：把 `build/CC-Relay.app` 拖到"应用程序"。第一次打开如被系统拦截，在"系统设置 → 隐私与安全性"里点"仍要打开"（应用是本地签名，没有经过 Apple 公证）。

### 1. 首次启动

- [ ] 打开本应用，点菜单栏图标。**预期**：每个已登录的 Claude 文件夹都成了一张账号卡片；名字是邮箱 @ 前面的部分（读到邮箱之前，默认账号显示"默认账号"，其他账号显示文件夹后缀）；大卡片是 Claude 正开着的那个账号。
- [ ] 打开设置。**预期**："开机自启"是关着的；"系统设置 → 通用 → 登录项"里没有 CC-Relay。

### 2. 额度与菜单栏

- [ ] 第一次读取额度时，系统会弹窗请求访问钥匙串"Claude Safe Storage"，选"始终允许"。**预期**：之后不再弹窗。
- [ ] 对照 claude.ai 网页"设置 → 用量"。**预期**：每个账号的 5 小时、每周剩余百分比与网页一致（剩余 = 100 − 已用，向下取整），重置时间一致；套餐和订阅渠道正确。
- [ ] **预期**：菜单栏里是当前账号的小伙伴，表情和颜色与面板里当前账号卡片上的一致，和旁边的图标一样大、方方正正，不显示账号名和百分比；平时静止不动；额度升到或降到另一档时换表情和颜色，升一档蹦一下，降一档叹口气；鼠标移到它上面时动起来，移开后停下；切换账号后换成新账号的小伙伴；点它照常打开面板。
- [ ] 平时不碰它，面板也收着。**预期**："活动监视器"里本应用的 CPU 占用接近 0。
- [ ] 打开面板看几秒，再收起。**预期**：打开时小伙伴、套餐标签照常动；收起后 CPU 占用马上回到接近 0。
- [ ] 在"系统设置 → 辅助功能 → 显示"里打开"减弱动态效果"。**预期**：菜单栏里的小伙伴静止，表情和颜色照常。
- [ ] 第一次打开面板后关闭，过 1 分钟再打开。**预期**：每个账号都有额度数字，小卡片上出现订阅渠道。
- [ ] 面板中间弹出"发现账号"时点"忽略"，再打开设置。**预期**：设置里有"已忽略的账号"，点"重新添加"后它回到卡片里。
- [ ] 点面板右上角的刷新箭头。**预期**：数字更新，不弹钥匙串窗口。
- [ ] 退出本应用，马上重新打开，立刻点菜单栏图标。**预期**：额度照常显示，不出现"需要钥匙串授权才能读取额度"，也不弹钥匙串窗口。
- [ ] （可选）断开网络后打开面板。**预期**：仍显示上次的数字，标注"更新于 HH:mm"。
- [ ] （可选）在 Claude 里退出某个账号的登录，再打开本应用的面板。**预期**：这个账号的卡片上额度的位置是红色小框"需要重新登录"，不再显示旧的数字；点它会切到这个账号，Claude 显示登录页，登录原来那个账号后卡片马上恢复。

### 3. 一键切换（没有正在运行的任务时）

- [ ] 在账号 A 里打开一段对话，再点账号 B 的卡片，在"切换到 B？"里点"切换"。**预期**：
  - 切换对话框里四步依次打勾；Claude 关闭后重新打开，是 B 账号；
  - Claude 自动回到刚才那段对话；
  - 之前同时开着的其他账号窗口也被重新打开（A 除外）；
  - 上方大卡片变成 B。
- [ ] 在 A 里新建一段对话，再切到 B。**预期**：B 的 Code 会话列表里能看到这段新对话（自动同步开启时）。
- [ ] 在 A 里归档一段对话，切到 B。**预期**：B 里这段对话同样是已归档状态。
- [ ] 打开设置 → 打开备份文件夹。**预期**：`Backups/` 里有 A 和 B 的时间戳备份。
- [ ] 点当前账号自己的卡片。**预期**：什么都不发生。
- [ ] 打开日志 `~/Library/Application Support/CC-Relay/Logs/cc-relay.log`。**预期**：上面每次切换都有一行 `Switch 原账号文件夹 -> 新账号文件夹: switched in N s`，失败的切换写明 `failed after N s` 和原因。

### 4. 切换前先压缩长对话（需要装好第 11 节的压缩插件）

对话有多大：每次切换后，日志里有一行 `Conversation context token total: N`。

- [ ] 在一段 30 万 tokens 以上、最近一小时用过的 Claude Code 对话里，等 Claude 回完，切换到另一个账号。**预期**：切换对话框显示"先压缩当前对话"、"正在压缩，约需 1–3 分钟…"和"跳过，直接切换"；这段对话自动执行一次 `/compact`（和你自己输入的一样，后面没有别的字）；压完后 Claude 才关闭，切到新账号后回到这段对话；面板中间弹出"切换前已压缩对话：约 N 万 → M 万"；日志里这次切换的一行带有 `compacted first: … tokens in N s`。
- [ ] （可选）从一段特别长的对话（例如 80 万 tokens 以上）切换，压缩超过 3 分钟。**预期**：对话框一直显示"先压缩当前对话"，等压完才关闭 Claude 接着切换，不会在压缩中途关掉；日志那一行写的是 `compacted first`，不是 `no answer`。
- [ ] （可选）从 30 万 tokens 以上的对话切换，压缩期间在另一段对话里让 Claude 开始一个任务。**预期**：压缩结束后、关闭 Claude 前，对话框换成"1 个 Code 任务正在运行"和三个选项，选"取消"什么都不变。
- [ ] 再从一段 30 万 tokens 以上的对话切换，在说明里点"跳过，直接切换"。**预期**：马上接着切换，结果里不提压缩；日志那一行写着 `compaction first skipped by the user`。
- [ ] 从不到 30 万 tokens 的对话切换。**预期**：不压缩、不弹说明，照常切换，结果里不提压缩。
- [ ] （可选）在设置里关掉"自动压缩"，再从 30 万 tokens 以上的对话切换。**预期**：不压缩，照常切换，结果里不提压缩。测完记得打开。

### 5. 任务守卫

- [ ] 在 Claude Code 里让 Claude 执行一个要跑一会儿的任务（例如运行一段要几分钟的命令），然后点另一个账号并点"切换"。**预期**：对话框里出现三个选项。
- [ ] 选"取消"。**预期**：什么都不变，任务继续。
- [ ] 再点切换，选"等任务结束后切换"。**预期**：对话框显示"正在等待任务结束…"；任务结束后几秒内自动切换，不再询问。
- [ ] 再开一个任务，点切换，选"立即切换"。**预期**：Claude 立即关闭（任务中断），不出现 Claude 自己的"Claude 仍在处理中"确认框，切换成功；之后不会留下继续在后台运行的 Claude Code 进程。

### 6. 默认启动纠正

- [ ] 60 秒内再做一次。**预期**：不再纠正，显示"自动切回已暂停 10 分钟"。

### 7. 添加账号

- [ ] 点"+ 添加账号"。**预期**：Claude 关闭后打开一个全新的登录窗口，添加对话框显示"在弹出的 Claude 窗口里登录新账号"。
- [ ] 用一个新账号登录。**预期**：
  - 对话框显示"正在导入历史会话…"，Claude 短暂关闭再打开；然后显示"已添加 ×××"和套餐、订阅渠道，停一下就消失；
  - 列表里出现新卡片，名字是邮箱 @ 前面的部分；

- [ ] 再添加一次，但在登录窗口出现后点"取消添加"。**预期**：Claude 回到原账号；`Archive/` 里多了一个 `Claude_xxxxxx-时间` 目录；面板没有多出账号。
- [ ] （可选）添加时登录一个已经存在的账号。**预期**：对话框写"这个账号已经在列表里了（×××）"，可选择"保留两个"或"放弃新添加的"。

### 8. 改名与移除

- [ ] 右键卡片（或点"⋯"）→ 改名，输入新名字回车。**预期**：卡片立即更新；超过 20 个字符时输入框下面红字说明，无法保存。
- [ ] 右键一个非当前、未打开的账号 → 移除并确认。**预期**：卡片马上消失，浮出"已移除 ×××"和"撤销"；4 秒后提示消失，`~/Library/Application Support/` 里该 `Claude_xxx` 目录被移到 `CC-Relay/Archive/`。
- [ ] 再移除一个账号，4 秒内点"撤销"。**预期**：卡片原样回来，目录还在原处。
- [ ] 右键当前账号。**预期**："移除"是灰的，下面写"正在使用的账号不能移除"。

### 9. 退出与开机启动

### 10. 打不开就回到原账号（可选，需要人为制造故障）

这个场景平时很难出现，可以跳过。如果遇到切换时目标账号没打开，**预期**：本应用自动重新打开原账号并回到原来的对话，切换对话框写"××× 没能打开，已回到 ×××。"。

### 11. 自动压缩（等额度自然用到 88% 以上时再测）

前提：已按《行为说明》第九节装好压缩插件。这一项要等当前账号的额度真的快用完，可以留到哪天正好用得多时再做。

- [ ] （随时可做）试压：挑一段不重要、10 万 tokens 以上的 Code 对话，发一句话，等它回完。在 `AutoCompact/sessions/` 里找到它的文件（文件名就是它的 sessionID），按 `docs/low-quota-compaction.md` 写一个 `test-request.json`。**预期**：半分钟内，这段对话自动压缩一次（和手动输入 /compact 时看到的一样）；CC-Relay 面板出现"已在额度用完前压缩对话：约 N 万 → M 万"；日志里有一行 `Auto-compact (early line): compacted`。
- [ ] 打开一段 Code 对话后打开设置。**预期**："自动压缩"开着（新装时默认关闭，打开时会先装插件）；下面一行显示"压缩插件已连接"。
- [ ] 正常使用一段长对话（10 万 tokens 以上），直到当前账号的 5 小时用量到 88% 左右（剩余 12%）。**预期**：Claude 回完那一轮后，这段对话自动压缩一次，看起来和你自己输入 /compact 一样（对话里只出现 /compact，后面没有别的字）；CC-Relay 面板中间弹出"已在额度用完前压缩对话：约 N 万 → M 万"；日志里有一行 `Auto-compact (early line): compacted`。同一个额度周期里不会再压第二次。
- [ ] （长任务）让 Claude 执行一个要跑很久的任务，到 92% 左右（剩余 8%）时还没做完。**预期**：任务在两个步骤之间停下，对话压缩，然后对话里出现不含项目名称的 "Continuation pauseID=…" 标记，正文只有 "Please continue the unfinished work from where it was interrupted, following the original instructions and scope of authorization."；中文和英文界面均使用这句英文，Claude 接着做；压缩结果由面板提示"已暂停任务并压缩对话……任务已自动继续"，以及本地回执记录。
- [ ] 压缩后切换到另一个账号，继续这段对话。**预期**：对话已经不到 30 万 tokens，切换时不再先压缩一遍；继续聊时新账号的额度下降得比不压缩时慢。
- [ ] （可选）关掉开关，下一个额度周期再用到 88% 以上。**预期**：不会自动压缩。
- [ ] 如果到了 92% 还没有压缩，或面板提示没压缩成功：记下时间、日志里那一行 `Auto-compact …`（行尾的 `Reason: …` 是原因）和设置里插件状态那一行。

### 12. 换号后原有工作接着做（需要装好第 11 节的同一个插件）

前提：自动同步开着；插件装好后已经重新打开过要测的会话。用一段专门的、不重要的测试会话，不要用正在做正事的会话。测试会话用"跳过权限"模式，或者事先允许这些命令：需要确认、或由自动模式判断的命令不托管，会随切换停掉。等后台命令真的跑起来再切换。这一项会关掉并重新打开 Claude。

- [ ] 准备：在测试会话里让 Claude 在后台运行一个会持续一阵的命令（例如每秒往文件里写一行数字、写满 600 行为止），再开一个监听（Monitor）和一个会跑几分钟的子代理。在 CC-Relay 里切换到另一个账号，任务守卫问时选"立即切换"。
- [ ] **预期**：新账号打开后，这段会话自动出现一条带"Continuation requestID=…"标记的续跑消息，正文只有 "Please continue the unfinished work from where it was interrupted, following the original instructions and scope of authorization."，不附长说明或 JSON 快照，Claude 接着做；后台命令写的数字从中断处继续往下，没有从 1 重新开始，也没有重复的行；监听接着报事件；子代理按原来的编号继续；面板中间先显示"正在接续"（图标是三个点），下面一行是"从 原账号 换到 新账号"；续跑这一轮做完后变成"接续成功"，图标换成对勾。
- [ ] 切换时这段会话正在回复（还在一步一步调用工具）。**预期**：Claude 重新打开后自己发的那句 "The app was quit while you were working…" 不执行（可能显示被插件拦下），由带"Continuation requestID=…"标记的续跑代替，只续跑一次；后台命令照常接回，数字不重复。
- [ ] 后台命令里用一个只在你的 shell 配置里定义的函数或别名。**预期**：切换前后都能正常运行，不报"找不到命令"。
- [ ] （有第二段会话时）切换前在另一段测试会话里也开一个后台命令，切换时确认只有目标账号的 Claude 开着。**预期**：那段会话会被自动打开并接着做，最后回到你切换前看的那段。
- [ ] 在 Claude 的后台任务界面停止那个后台命令。**预期**：文件不再增长，面板不出现"接续受阻"。
- [ ] 切换后发一条新消息打断自动续跑。**预期**：自动续跑让位，不会再自己继续；面板不把它算成"接续受阻"。
- [ ] 续跑那一轮还在进行时按回车发一句话（例如"顺便把 README 也更新一下"）。**预期**：续跑这一轮马上停下，你的话在新的一轮里执行，能正常读写文件；面板不出现"接续受阻"。下一次切换后改用 ctrl+x 回车排队发，或者输入一条斜杠命令（例如 /context）：结果一样，续跑这一轮马上停下。
- [ ] 续跑做完、面板显示"接续成功"以后，再发一句话或按一次停止。**预期**：面板上的状态不变。
- [ ] 在一段正在回复的对话里先按停止，再切换。**预期**：这段对话不会自动接着做，面板也不提示"接续受阻"。
- [ ] 让一段测试会话在后台跑写数字的命令，然后只按停止停掉回复（不停后台命令），再切换。**预期**：这段对话不会自动接着做；面板出现普通提示"切换时结束了 1 个后台命令"，不是警告样式。
- [ ] 一段会话的上下文很长时，先在里面输入 /compact，趁压缩还没结束就开始切换。**预期**：切换等压缩做完，切换结果里不出现"对话没能先压缩"。
- [ ] 记录：如果有一项没接上，记下时间和面板显示的状态，不要重试同一个命令。

### 13. 自动切换（需要装好第 11 节的同一个插件，并在设置里打开"自动切换"）

用专门的测试会话，等额度自然用完；不要为了测试刻意耗尽额度，也不要伪造限流。

- [ ] 测试会话在后台跑一个已允许的命令（例如每秒往临时文件写一行数字），另有一个额度充足的账号。**预期**：额度用完后不弹任何确认，自动换到那个账号；命令是同一个进程，数字不中断、不重复；原会话接着做。
- [ ] 额度快用完时，让测试会话在后台跑一个需要你点授权才运行的命令。**预期**：命令跑完之前不换号，面板说明暂时不换的原因；命令结束后自动换号。
- [ ] 测试会话处在"跳过权限确认"模式，额度充足的账号里只有一个开了"跳过权限确认"。**预期**：自动换到开了的那个账号。都没开时不换号，面板提示"能用的账号都没开“跳过权限确认” / 手动切换到 {账号名}，在那里打开"。
- [ ] 限流报错换号后，新账号 10 分钟内又报限流，而它的额度还有余量。**预期**：不再换号，Claude 不被再次关闭，面板显示"刚换过号又遇到限流，先不再换"；限流信号结束或会话恢复正常回复后提示消失。
- [ ] （遇到时记录，不要刻意制造）Claude 报错说账号被暂停或组织不允许使用。**预期**：不自动换号，Claude 不被关闭，面板显示"这个账号被暂停或不允许使用"；会话恢复正常回复后提示消失；手动切换照常。

- [ ] 额度用完时，会话里有一条需要授权才运行的命令还在跑。**预期**：先不换号，面板不出提示；命令结束后自动换号。
- [ ] 手动切到一个额度已经用完的账号，测试会话的后台命令还在跑，进去以后什么都不动。**预期**：半分钟左右后自动换到有额度的账号，托管的后台命令跟着过去，面板不出暂停提示。
- [ ] 额度用完时，开着的 Code 会话都已经做完（没有正在回复，也没有后台命令），或者没做完的那段回复已经被你停止。**预期**：照样换到有额度的账号（Claude 关掉再打开）；做完的会话不会自己发消息，你停止的那段回复也不会被接着做。

### Artifact 评论监听与自动回复

以下为打包安装后、使用专门测试会话的真实验收项；本地测试通过不等于这些已完成。

- [ ] 在测试会话发布一个可编辑的 Artifact，确认发给 Claude 的评论会得到一次自动回复。完成主回合，仅保留评论监听，然后退出重开该会话。**预期**：恢复原网页监听和自动回复；无额外的主任务续跑消息；新评论只回复一次。
- [ ] 对同样只有评论监听的空闲会话手动换号。**预期**：该会话不被打开，也不收到任何续跑消息；面板提示"评论监听留在了 {原账号}（1 段会话）"并列出会话标题。再切回原账号。**预期**：这段会话在后台启动，不出现"接着做"的新回合，监听接上，发给 Claude 的评论只回复一次；面板上的提示消失。
- [ ] 一段会话挂着评论监听，同时还在做事，手动换号。**预期**：活在新账号接着做；面板不提示"接续受阻"，提示"评论监听留在了 {原账号}（1 段会话）"；续跑回合不去监听或重新发布那个网页。等它做完再切回原账号。**预期**：这段会话只为监听在后台启动，不出现"接着做"的新回合，监听接上；面板上的提示消失。
